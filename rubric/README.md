# Evaluation rubric

The rubric has three parts that must not be confused with each other:

| File | Purpose | Nature |
|---|---|---|
| [`dimensions.md`](dimensions.md) | Ten evaluation dimensions (D-01 … D-10) with behaviorally anchored five-level descriptors | Judgment, anchored in evidence |
| [`scoring.md`](scoring.md) | How levels become device-specific results; confidence; N/A and insufficient-evidence outcomes; severity; provisional weights; blocking conditions | Procedure |
| [`quality-gates.md`](quality-gates.md) | Objective, verifiable requirements (QG-xxx), separated into *standards* and *recommended thresholds* | Pass / fail / not verified |

A review produces **separate results per device context** (mobile, desktop, responsive transitions, PWA behavior) plus an **overall cross-device task-effectiveness judgment**. A serious failure on any supported device is never averaged away. See `scoring.md`.

The evaluation *method* (screenshot, prototype, running app, automated tests, user study) determines what can be claimed. See [`../evaluation/methods.md`](../evaluation/methods.md).
